# Contributing to Twin Peaks 2.0

Twin Peaks 2.0 is the governing spine of Phoenix Gateway OS.
It is a clean-artifact repo. Everything that enters is finished,
authoritative, and Gauntlet-passed. Nothing else lands here.

---

## The Gate

Every change enters through a Pull Request. Shane reviews and merges.
No agent, no human, no automation commits directly to main. Ever.
This is not a policy preference. It is the structural law of this repo.

---

## The Landing Pass

Before a PR can be reviewed by Shane, it must pass the Landing Pass.
The Landing Pass checklist is in .github/PULL_REQUEST_TEMPLATE.md.
Every checkbox must be checked. Not skimmed. Not assumed. Checked.

A contribution earns a Landing Pass when:
1. It passes the Clean-Artifact Law (see 00_GOVERNANCE/CLEAN_ARTIFACT_LAW.md)
2. It conforms to the Function Folder format (see 00_GOVERNANCE/FUNCTION_FOLDER_TEMPLATE.md)
3. It has been through the Gauntlet (see README.md)
4. It states what it is — no more, no less

---

## The Clean-Artifact Law

A clean artifact contains only what it is.

A clean artifact never contains:
- Notes to self
- TODOs, reminders, or deferred tasks
- Process chatter or meta-commentary
- Hedges, maybes, or unresolved questions
- Placeholder text left in from drafting

If it would not appear in a published technical document,
it does not appear here.

---

## Authority Order

Shane Warehime is the sole merge authority on main.
No PR merges without his explicit approval.
No exceptions. No urgency overrides this.

---

## The Staging Ground

Work that is not ready belongs in the twin-peaks repo (staging).
Gauntlet work happens there. Drafts live there.
Clean, finished, Gauntlet-passed artifacts come here.

---

## Archive, Never Delete

Nothing is deleted from this repo.
Superseded content is archived in place.
The archive record is preserved.
